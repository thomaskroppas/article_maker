## T-0. Проверка окружения

### [BLOCKER] XMLStock недоступен из среды разработки Claude Code (web)

**Что проверялось (команда из CLAUDE.md):**

```bash
curl -m 10 "http://95.217.108.20:8085/api/v1/parsers/xmlstock/serp?q=test&geo=ru&hl=ru"
```

**Результат:** `Connection timed out` (HTTP 000).

**Причина — ограничение сети именно этой среды разработки, а не факт недоступности XMLStock:**
Разработка ведётся в облачной песочнице Claude Code с политикой egress, где весь
исходящий трафик идёт через agent-proxy. Прокси принимает **только HTTPS
CONNECT-туннели на стандартные порты**. Эндпоинт XMLStock — это **обычный HTTP**
(не HTTPS) на **сыром IP `95.217.108.20`** и **нестандартном порту `8085`**.
Такой трафик (plain-HTTP, non-443, raw-TCP) прокси не пропускает by design
(`/root/.ccr/README.md`, раздел «Not supported through the proxy»). Проверка
`-x $HTTPS_PROXY` подтверждает: прокси возвращает `405 — this proxy only accepts
HTTPS CONNECT tunnels`.

**Вывод:** из песочницы разработки XMLStock физически не проверить. Это **не**
означает, что парсер лежит: при реальном запуске `docker compose up` на
инфраструктуре заказчика (его сеть/VPS) сервис `backend` обращается к XMLStock
напрямую, без этого прокси, и, вероятно, доступен.

**Действие / что нужно от заказчика:**
1. Заказчику — **проверить XMLStock со своей стороны** одной командой выше и
   подтвердить, что она возвращает JSON. Это необходимо для приёмки Этапа 1
   (без живого парсера приёмка не пройдёт — CLAUDE.md, раздел «Проверка окружения»).
2. Разработка при этом **не блокируется**: шаги 2+ пайплайна ведутся на
   `fixtures/serp_bundle_example.json` через `serp_json_path`, XMLStock в тестах
   не вызывается (CLAUDE.md, «Тестовая дисциплина»).

**Статус:** ожидает подтверждения заказчика; на дальнейшие задачи (T-1+) не влияет.

## T-1. Каркас и Docker Compose

### [ДОПУЩЕНИЕ] Полный `docker compose up -d` не проверяется из среды разработки

В облачной песочнице Claude Code **нет Docker-демона** (доступен только CLI
`docker compose`, которым провалидирован конфиг: `docker compose config` → OK,
5 dev-сервисов). Поднять весь стек и открыть :3000/:8000 целиком здесь нельзя —
это среда без daemon, а не дефект конфигурации.

**Что проверено напрямую:**
- `GET /api/health` → 200 (`{"status":"ok"}`) по реальному HTTP через uvicorn,
  плюс `pytest` (3 passed); Swagger `/api/docs` → 200.
- Фронтенд: `npm run build` (Vite) собирается без ошибок; dev-сервер настроен на :3000.
- `docker compose config` валиден; образы `pgvector/pgvector:pg15`, `redis:7`,
  сборка backend/worker/frontend, nginx под profile `production`.

**Действие:** полный `docker compose up -d` с проверкой :3000/:8000 выполняется
на хосте с Docker-демоном (машина заказчика / приёмка T-14). Ожидание — поднимется
штатно; конфиг и оба образа-приложения к этому готовы.

**Решение заказчика — вариант 1 (нормализация на входе) с уточнениями:**
- (a) весь маппинг legacy → §13 собран в одном модуле

  `# legacy desktop-format compatibility` (не размазаны по схемам);

- (c) выходной контракт пайплайна строго §13 — обязательный тест

Модели §13 объявлены строго по ТЗ (поля/типы не менялись). SerpBundle/LSI/
